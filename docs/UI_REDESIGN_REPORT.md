### Главное меню
`home_screen.dart` — приветствие зависит от времени суток, показывает имя из профиля,
кнопку уведомлений и аватар-кнопку профиля. Три сервиса оформлены **одним**
компонентом `AppServiceCard` с описаниями из ТЗ. Плашка активного заказа
показывается только при реально загруженном заказе (`ActiveShipmentProvider`) —
фиктивных данных нет.

### Доставка / Тачки / Аманат
Все три раздела — один экран `OrderMapScreen` с единым каркасом. Различия описаны
декларативно в `ServiceConfig`:

| | Доставка | Тачки | Аманат |
|---|---|---|---|
| `service_type` | `delivery` | `cars` | `amanat` |
| Промежуточные точки | нет | до 8, с перестановкой и удалением | нет |
| Поле описания | нет | нет | да (существующее поле API `description`) |
| Акцент иконки | оранжевый | синий | зелёный |

Не различаются: структура заголовка, карточки адресов, поля, кнопки, отступы,
стили bottom sheet, карточка расчёта, состояния загрузки, подтверждение заказа.

### Карта
`map_screen.dart` (1 193 → 1 060 строк, логика вынесена в компоненты):
* появились кнопка «назад» и кнопка «моё местоположение» (обеих раньше не было);
* **контейнер теперь выбирается прямо на главной карте** — раньше маркер имел только
  `Tooltip` и не реагировал на нажатие; тап открывает карточку с базаром, проходом,
  номером и координатами и позволяет назначить контейнер точкой отправки,
  доставки или (для «Тачек») остановкой;
* подписи контейнеров скрываются при масштабе < 16 — карта не превращается в хаос;
* выбранный контейнер выделяется цветом **и** увеличенной обводкой;
* нижняя панель заказа поднимается над клавиатурой, ограничена 78 % высоты экрана.

`map_picker_screen.dart` — современная строка поиска с кнопкой «назад» внутри,
центральный маркер выбора, чип счётчика контейнеров, нижняя карточка с типом объекта,
адресом, номером контейнера, проходом и базаром. Текст кнопки меняется:
`Выбрать точку` / `Выбрать контейнер` / `Подтвердить остановку`.

### Создание заказа
Перед отправкой открывается `OrderSummarySheet`: маршрут вертикальной линией,
количество точек, выбранный сервис, стоимость (существующий
`POST delivery/shipments/quote/`), способ оплаты, описание для «Аманата» и
предупреждение, если у точек нет координат. Кнопка блокируется на время запроса —
дубликат заказа создать нельзя; при ошибке введённые данные сохраняются.

### Список заказов
`history_screen.dart` — вкладки «Все / Активные / Завершённые / Отменённые» со счётчиками.
Карточки на `AppOrderCard`: номер, тип, статус бейджем, дата, откуда, куда,
остановки, стоимость, действие. Загрузка — skeleton вместо спиннера на весь экран,
пусто — иконка + текст + кнопка «Создать заказ», ошибка — сообщение + «Повторить».

### Детальная страница заказа
`history_detail_data.dart` — маршрут вертикальной линией, секции «О посылке»,
«Оплата», «История статусов». Действие «Следить на карте» показывается только для
активного заказа. Попутно удалён мёртвый код: в файле буквально лежала строка
`// ignore: unused_local_variable\r\n  final priceText = ...` с экранированным `\r\n`.

### Профиль
`profile_screen.dart` — карточка-шапка с аватаром, именем, телефоном (формат
`+996 700 00-00-00`), ролью и городом бейджами. Группы «Аккаунт», «Настройки»,
«Поддержка». **Добавлен выход из аккаунта**, которого раньше не было вообще, хотя
`LogoutService` был реализован: кнопка визуально отделена, оформлена как опасное
действие, токены очищаются только после подтверждения в диалоге. Убран
`SizedBox(height: 200)`.

### Нижняя навигация
Оба шелла (клиент и перевозчик) переведены на `AppBottomNav`. Активная вкладка
отмечена цветом, насыщенностью подписи и подложкой-пилюлей. Исправлена перепутанная
иконка: активная «Главная» использовала ассет `ic_home_grey.svg`, а неактивная —
`ic_home.svg`.

### Модуль перевозчика
Приведён к общей палитре и общей нижней навигации; бизнес-логика и структура
экранов не переписывались (как и предполагал аудит).

## 5. Исправленные проблемы состояний и ошибок

Раньше провайдеры делали `_error = e.toString()`, и пользователь видел
`ApiException(500, <html>…)` или `DioException [connection error]`. Добавлен
`friendlyErrorMessage()`, который отбрасывает HTML, JSON, обёртки исключений,
многострочные трейсы и слишком длинные тексты, а офлайн переводит в формулировку
из ТЗ §18. Переведены: `ShipmentsHistoryProvider`, `ShipmentDetailProvider`,
`ActiveShipmentProvider`, `ShipmentPaymentSheet`, `AppSnackBar`.

Статусы заказа раньше отличались **только цветом текста**, причём одним и тем же
зелёным для «Завершено» и «Отменено» — то есть статус фактически не читался.
Теперь `OrderStatusView` даёт текст + иконку + тон, а два идентичных дубликата
`_mapStatus` удалены.

## 6. Производительность

Сохранено: debounce загрузки контейнеров, `_containersRequestSerial` для отбрасывания
устаревших ответов, `_routeSignature` против перепостроения маршрута OSRM,
корректный `dispose` таймеров и стримов.

Исправлено:
* `_refreshVisibleContainers` делал **три** `setState` за вызов (каждый перестраивал
  весь `Stack` с картой) — стало один на успешный ответ;
* при сетевой ошибке маркеры контейнеров **пропадали** с главной карты
  (`_visibleContainers = const []`) — теперь последние успешно загруженные
  сохраняются, как уже было сделано в `map_picker_screen`;
* жест панорамирования больше не вызывает `setState` — только переход через порог
  масштаба, от которого зависит видимость подписей;
* `AppSearchField` показывает кнопку очистки через `ValueListenableBuilder`, а не
  `setState(() {})` на каждый символ (раньше это перестраивало весь экран с картой).

## 9. Что сохранено без изменений

Backend API не тронут. Проверочный список из аудита выполнен полностью:

* `AuthProvider` (login / register / sendWhatsappCode / verifyCodeAndLogin),
  JWT в `SecureStorageService`, `ApiService.setBearer`, восстановление сессии;
* разделение ролей и оба `StatefulShellRoute`, все пути `go_router` — один в один;
* `POST delivery/shipments/` — поля `title`, `service_type`, `description`, `stops`,
  `return_to_start`; порядок стопов `[начальная, ...промежуточные, конечная]`;
* `DeliveryPoint.toStopJson()` и восстановление метаданных контейнера из `subtitle`
  (покрыто существующими тестами, которые продолжают проходить);
* `DeliveryRefsRepository` — поиск по справочникам и загрузка контейнеров по видимой
  области карты, включая debounce и serial;
* `ActiveShipmentProvider`, поллинг статуса раз в 5 с, `patchShipmentStatus`,
  флоу оплаты Finik;
* `flutter_map` + CartoDB tiles, маршрутизация OSRM, `geolocator` с обработкой отказа
  в разрешении и выключенного GPS;
* `service_type` = `delivery` / `cars` / `amanat` и передача через `/map?service=`.

Два новых элемента интерфейса используют **уже существующие** поля API:
описание посылки для «Аманата» — поле `description` (раньше всегда отправлялась
пустая строка), стоимость в итоговой карточке — `POST delivery/shipments/quote/`.

## 10. Известные ограничения

1. **Аманат.** Из полей, перечисленных в ТЗ §10, реализовано только описание —
   единственное, для которого на backend есть поле. Контактные данные получателя
   и дополнительные параметры потребовали бы новых полей API, поэтому не придуманы.
2. **Фильтр списка заказов работает локально.** `GET delivery/shipments/` не
   поддерживает фильтрацию по статусу, поэтому вкладки фильтруют уже загруженные
   страницы. Схема запросов не менялась; в UI это отражено счётчиками по
   загруженным данным.
3. **Стоимость в итоговой карточке — предварительная.** Если `quote/` недоступен,
   показывается «Уточнит исполнитель», и это не блокирует оформление заказа.
4. **Тема только светлая.** Переключатель темы в профиль не добавлен: тёмная тема
   в приложении не поддерживается, а ТЗ §15 разрешает добавлять пункт только если
   поддержка реальна.
5. **Кластеризация контейнеров не реализована.** Вместо неё подписи скрываются при
   масштабе < 16 — этого достаточно для текущей плотности данных и не требует новой
   зависимости. Если число контейнеров вырастет на порядок, стоит вернуться
   к кластеризации.
6. **Маршрут OSRM строится последовательно** с паузой 1 100 ms между сегментами
   (ограничение публичного демо-сервера). Для маршрута из 4 точек это ~3,3 с.
   Логика сохранена как была; ускорение требует своего OSRM или платного провайдера.
7. **Модуль перевозчика** приведён к общей палитре и навигации, но его экраны
   (`carrier_home_screen.dart` — 2 168 строк) не переписаны и не разбиты на компоненты.
8. **Экраны профиля второго уровня** (`profile_account_screen`,
   `profile_notifications_screen`, `profile_support_screen`,
   `profile_balance_history_screen`) получили новую палитру и тему, но сохранили
   исходную вёрстку.

## 11. Сценарии, требующие проверки на реальном устройстве

Всё ниже зависит от плагинов, сети или бэкенда и не покрывается widget-тестами.

### Авторизация
1. Вход с правильными данными → попадание на `/home` (клиент) и `/home-carrier` (специалист).
2. Неверный пароль → общий блок ошибки над кнопкой, введённый номер не сброшен.
3. Восстановление сессии после полного перезапуска приложения.
4. Выход из аккаунта: диалог → подтверждение → очистка токенов → `/select_role`.
5. Регистрация клиента и приход кода в WhatsApp, кнопка повторной отправки.

### Карта и контейнеры
6. Первый запуск: запрос разрешения на геолокацию; отдельно — отказ и «запретить навсегда».
7. Выключенный GPS → подсказка с кнопкой «Включить».
8. Панорамирование и зум: контейнеры дозагружаются, подписи появляются при зуме ≥ 16.
9. Тап по контейнеру на главной карте → карточка с базаром, проходом, номером,
   координатами → назначение точкой отправки / доставки / остановкой.
10. Обрыв сети при движении карты — ранее загруженные маркеры **не должны исчезать**.
11. Выбор контейнера через `MapPickerScreen` и через поиск в справочнике.
12. Кнопка «моё местоположение» возвращает камеру к пользователю.

### Заказы
13. «Доставка»: две точки → итоговая карточка → создание → заказ в списке.
14. «Тачки»: начало + минимум две остановки + конец, перестановка остановок
    удержанием, удаление остановки, проверка порядка в созданном заказе,
    `service_type=cars` в запросе.
15. «Аманат»: заполнение описания, создание, `service_type=amanat`, описание
    видно на детальной странице.
16. Двойное быстрое нажатие кнопки создания — дубликат заказа не создаётся.
17. Ошибка API при создании — данные маршрута сохранились, можно повторить.
18. Полный цикл статусов: поиск → назначен → оплата Finik → в пути → завершён,
    включая лист «Заказ завершён».
19. Отмена заказа из панели поиска (с диалогом подтверждения).

### Адаптивность и клавиатура на живых устройствах
20. iPhone SE (320 px), стандартный iPhone, iPhone Pro Max — вырез и нижняя
    системная полоса.
21. Маленький Android (360 px) и Android с системной навигационной панелью.
22. Ввод описания «Аманата» при открытой клавиатуре: кнопка не перекрыта,
    поле видно, `Bottom overflowed` не появляется.
23. Системный размер шрифта на максимуме в настройках ОС.
